# Audit Event Catalog

This catalog is the source-backed coverage ledger for the Audit Log Foundation. It records the
current branch contract; it is not a promise that every write in the platform belongs in the
central Audit collection.

## Coverage rules

- **Audited**: the mutation emits a central event through `src/modules/audit/public.js`.
- **Domain-history-only**: an existing aggregate history remains the source of truth and is not
  duplicated centrally.
- **Intentionally skipped**: the route is a preview, acknowledgement, queue command, or a
  mutation outside the approved highest-risk foundation scope.
- A no-op may emit no new event where the owning service explicitly treats the replay as unchanged.
- Central metadata never stores passwords, tokens, credentials, raw payroll amounts, uploaded file
  contents, attachment contents, raw import rows, free-form notes/reasons, or unnecessary PII.
- HTTP request IDs are correlation fields, not mutation identities. Deduplication uses persisted
  entity/transition identity or a server-owned operation ID.
- Existing `MappingRuleAudit`, `OrderTimeline`, and `VendorSubmission.statusHistory` remain intact.

## Event field contract

| Field | Rule |
| --- | --- |
| `actorType` | `ACCOUNT`, `SYSTEM`, or `ANONYMOUS`; `actorAccountId` is present only for a known account. |
| `source` | `HTTP`, `WORKER`, `SYSTEM`, or `IMPORT`, selected by the mutation owner. |
| `entityType` / `entityId` | Stable owning aggregate type and persisted identifier; never a secret or raw user identifier. |
| `scopeType` / `scopeId` | `SHOP`, `TEAM`, or `DEPARTMENT` when one conservative scope is known; otherwise both are null. |
| `metadata` / `changes` | Allowlisted identifiers, statuses, safe field names, dates, booleans, and counts only. The Audit validator recursively removes dangerous/sensitive keys and enforces depth/size bounds. |
| `requestId` / `ipAddress` / `userAgent` | Bounded HTTP provenance where controllers supply it. |
| `deduplicationKey` | Required, unique, server-owned operation identity. |

## Sensitive read coverage

Sensitive reads are tracked separately from the mutation-route ledger. The **199-route mutation
inventory and its 132/22/45 classification remain unchanged**. These events are written only after
the authenticated read succeeds; an Audit write failure fails the read instead of silently losing
the evidence. Metadata contains only allowlisted filters, stable IDs, booleans, statuses, dates, and
counts. It excludes credentials, tokens, raw financial/payroll values, free-form notes, raw rows,
buyer data, and other unnecessary PII.

## Verification ownership

- Route inventory is source-derived, not inferred from API documentation.
- Each ledger row links executable route/controller/service behavior evidence.
- Audit contract, query authorization, transaction semantics, sanitization, deduplication, and
  index lifecycle have dedicated Audit tests.
- Production index proof must run only against a disposable isolated MongoDB test database; never
  point `npm run indexes:audit` at the default `.env` database for verification.
